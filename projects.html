Industrial Equipment Configurator (CPQ)

  • React
  • Vite
  • Three.js
  • jsPDF
  • Docker
  • Nginx

A web-based Configure-Price-Quote tool for configurable industrial hardware. An engineer picks the product type, enters electrical specs and dimensions, and gets a live bill of materials, a full cost rollup, a 3D preview, and a downloadable quote, all in the browser with no backend.

The hard part was that all the pricing and engineering logic lived in giant, battle-tested spreadsheets. I ported those formulas straight into a JavaScript calculation engine so the numbers stay precise and round exactly the way the engineers expect, then made the whole thing recalculate live as inputs change.

What it does

  • Real-time BOM and cost engine with multi-currency support and configurable lot sizes up to thousands of units.
  • Interactive 3D product visualization (Three.js) sitting right next to the configuration panel.
  • A manufacturing process routing view that lays out the real sequence of work-center operations with time and cost estimates.
  • Client-side PDF generation (jsPDF) that produces a complete spec sheet with drawings, BOM tables, and cost breakdowns, no server round-trip.
  • Shipped as a static bundle behind Nginx in a Docker container, with cloud deployment scripts.

Stack

React + Vite single-page app, Three.js for 3D, jsPDF for documents, Docker + Nginx for delivery.

AP Invoice Automation Platform

  • Node.js
  • Express
  • MongoDB
  • React
  • Node-RED
  • Azure AD SSO
  • Docker

An accounts-payable platform that ingests vendor invoices, pulls the matching purchase orders from the ERP, runs a multi-tier matching engine, flags discrepancies, and lets AP staff review and post vouchers straight from a dashboard.

Real vendor invoices are messy. The interesting work was teaching the system to read them the way a human in AP would, then reconcile every line back to the purchase order down to the penny before anything gets posted.

Matching engine

  • A low-code intake pipeline (Node-RED) normalizes incoming invoices and fetches the related POs before matching begins.
  • Three-pass line pre-processing: split merged invoice lines, rewrite vendor part numbers to the canonical ERP item IDs when the math closes, then fold surcharges and setup fees into the right product lines.
  • Unit-of-measure aware comparison that skips quantity and unit-price checks for non-each units (length, weight) and judges by extended amount, which is how vendors actually bill.
  • Several posting paths depending on match status (clean match, variance with line detail, partial match, freight and service by amount), all built around the ERP needing penny-exact totals.
  • Configurable per-vendor tolerance bands so expected variances don't get falsely flagged.

Dashboard

  • KPI cards, trend sparklines, clickable aging buckets, vendor breakdowns, and payment-lag tracking, with week-over-week, month-over-month, and year-over-year comparisons and CSV export.

Stack

Node.js + Express REST API, MongoDB, React dashboard, Microsoft SSO via Azure AD, three-container Docker deployment (API, frontend/Nginx, database).

Field Survey Mobile App

  • React Native
  • Expo
  • TypeScript
  • SQLite
  • Offline-first

A cross-platform iOS and Android app for field technicians to survey equipment on site. Photograph the machine, drop numbered pins on each component, fill a guided spec form per pin, save offline, and sync when you're back in range.

Technicians work in places with no signal, so the whole app had to keep working with zero connectivity and then sync cleanly later, even if two people surveyed the same machine. That sync and conflict story was the real engineering challenge.

Offline + sync

  • Offline-first by design: a local SQLite database is the single source of truth, so nothing depends on a live connection.
  • Write-through outbox pattern queues every change keyed by a client-generated UUID, so syncs are idempotent and nothing gets lost or applied twice.
  • Multi-device conflict resolution with field-level merge: only fields two devices set differently need a human choice, everything else auto-merges and re-pushes so the winning value is definitive.
  • Append-only schema migration system (15+ migrations) so the on-device database upgrades cleanly across app versions.

Capture tools

  • Custom annotation screen with pinch-zoom on the photo and independent resize of each pin.
  • A 2D component diagram where techs tap to place and drag features with real dimensions, all serialized to JSON and synced end to end.
  • Built with pluggable seams for transport, auth, and shape definitions so real implementations drop in without reworking call sites.

Stack

React Native + Expo, TypeScript, on-device SQLite, EAS cloud builds.

AI Survey Digitization

  • Node.js
  • Express
  • React
  • Vision LLMs
  • MongoDB
  • Docker

A full-stack web app that turns handwritten field-survey forms into structured, searchable data using vision-capable LLMs, then scores the results against an ERP parts catalog to suggest matches. It also doubles as the sync backend for the mobile app above.

The input is handwriting on paper, which no two people fill out the same way. The goal was to pull clean, structured specs out of that and line them up against real catalog parts, with a human reviewing before anything is trusted.

OCR + matching

  • Dual-provider OCR engine: two vision models run behind one shared prompt and identical JSON schema, and a compare endpoint runs both in parallel for side-by-side accuracy benchmarking and cost control.
  • Weighted-score matching engine ranks catalog parts against the extracted specs on a points system (exact ID, dimensions with millimeter tolerances, wattage, type, voltage, termination) so the best candidates surface first.
  • Server-side PDF splitting breaks multi-page uploads into single pages before OCR to keep batches within model limits.
  • Handles survey shorthand like "same as #N" by resolving those cross-references during extraction.
  • Catalog auto-imports from a spreadsheet on first startup, so there's zero manual setup.

Stack

Node.js + Express server, React review UI, two vision LLM providers behind one interface, MongoDB, Docker + Nginx. Also exposes the REST sync endpoints that back the mobile app.
